# E8 收容事故（0.12.0-alpha.6）

Forge 1.20.1 和 NeoForge 1.21.1 同步提供中央研究所 B2 层 E8 事故实验室事件。随 [alpha.6](https://github.com/fl749731-lab/ender-infection/releases/tag/v0.12.0-alpha.6) 发布。没有加入研究所 Boss。

## 开始与完成

1. 修复原有发电机，开启收容区供电；通过显微镜完成样本分析，再通过离心机完成分离。保留研究门禁卡。
2. 生存或冒险模式下，主手持门禁卡右键 **E8 内的研究终端**。服务区供电可以保持原来的设置；启动时收容区必须有电，且难度不能是和平。
3. 约三秒警报后出现第一波三只感染者。清除后再间隔约三秒出现第二波三只；每所研究所总共最多六只，不会循环刷怪。
4. 主手持 **2 个铜锭**右键冷却泵；主手持 **1 个红石粉**右键监视器。两处故障可以提前修复，重复操作不重复扣材料。
5. 清除两波并修好上述设备后，**主手空手、潜行右键管道隔离阀**，完成隔离复位。
6. 背包留出空间，右键 E8 终端领取 **研究记录 ×1、虚空晶体 ×1**。一所研究所的全体玩家共享一次奖励；满背包不会消耗领奖资格。

冷却故障只切断 E8 的受管照明与设备供电。终端和两盏闪烁的红石警报灯使用独立应急供电；原有全所配电开关、其他房间和室内应急开门功能继续工作。研究日志可以查看阶段、已清除数量和剩余故障数。

第一波为潜伏觅食虫、早期感染僵尸、裂喉喷吐者；第二波为潜伏觅食虫、晶盾卫士、早期感染骷髅。此事件不生成母体或 Boss。

## 存档与扩展行为

- 阶段、计时、故障、六个预留实体 UUID、最后位置、已生成和已解决名额、共享领奖资格保存在每个维度的 `ender_institute_operations` SavedData。旧供电和研究进度保持兼容。
- 没有存活的生存／冒险玩家在房间附近时暂停推进；房间或尚未解决敌人的最近位置区块未载入时也暂停，不主动加载区块。
- 已生成名额不会因实体暂时找不到而补刷，也不会将找不到的实体当作被击败。刷怪位置被堵时只重试未成功的固定名额。
- 切换和平难度会退休已经用掉的名额，且不产生战利品；切回其他难度只推进剩余名额。卸载中的已退休实体再次载入时会被移除。
- 缺损或未知的活跃存档进入恢复保护状态，停止推进，避免重置事件造成重复刷怪或领奖。若管理员通过指令永久删除了未击败的事件实体，需要恢复备份；系统不会为此无限补怪。
- 公共 API 契约未变。既有 `FacilityEvent.reason()` 新增 `incident:E8:` 前缀，后缀包括 `started`、`wave_started`、`first_wave_cleared`、`isolate`、`repaired:cooling`、`repaired:sensor`、`repaired:valve`、`reward_claimed`。供电／研究快照在这些通知中可能不变；附属 Mod 应忽略自己不认识的原因。

## 验收方式

两版均提供 `runGameTestServer -PincidentChecks`，覆盖完整流程、多人与前置、部分刷怪失败、缺失实体、和平模式、无人暂停、满背包和本地电力恢复。

`python tools/check_incident_persistence.py` 会为每版创建独立 `build/incident-persistence-*` 世界并启动三次真正的专用服务器，验证活跃状态重启、区块实际卸载／重载、结束领奖后再次重启。仅监听本机随机端口，不使用玩家的 Minecraft1201 实例。断电或进程被强制杀死时，恢复范围仍以 Minecraft 最近一次完成的世界保存为准。

`runClient -PincidentVisualCheck` 使用四个真实结构片裁出 E8 房间，通过客户端原生交互包完成启动、修复和领奖。测试夹具预先满足研究前置并代为击杀敌人；它不是玩家战斗难度或完整研究流程的自动通关证明。截图与日志见[本轮验收目录](../previews/incident-alpha6/README.md)。完整发布门槛仍是 `python tools/build_dual_version.py --clean --gametests`。
