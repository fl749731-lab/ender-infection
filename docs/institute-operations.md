# 研究所供电与样本研究

适用于主模组 **0.12.0-alpha.7**。本页操作最初于 alpha.4 接入；当前下载见[alpha.7 发布页](https://github.com/fl749731-lab/ender-infection/releases/tag/v0.12.0-alpha.7)。Forge 1.20.1 / Java 17 与 NeoForge 1.21.1 / Java 21 同步提供。

本轮把中央研究所的探索连成“取得物资 → 修复电源 → 分区送电 → 领取门禁卡 → 分析与分离 → 领取核心档案”。完成研究后可继续 [E8 收容事故](containment-incident.md)；研究所 Boss 尚未接入。

## 从哪里开始

新玩法使用 **新生成或新施工中央研究所**。自然生成需要探索新的合适区块；管理员也可按[中央研究所施工说明](central-institute.md)检查空地并施工。已存在的 alpha.3 建筑不会自动拆除或重建，旧布局也不会悄悄补上控制器或任务绑定。更新 JAR 不会重抽已经领取的储物战利品。

先在 G1 公共区寻找补给桶，取得保险丝、原始组织样本和研究日志；公共分类补给保证提供这些起步物品。修复还需要铜锭、红石。保险丝可用铁粒和红石合成。手持 `ender_infection:research_log` 右键可查看当前位置研究所的当前目标。

## 四个操作点

| 房间 | 设备 | 操作与作用 |
| --- | --- | --- |
| B1 / D2 应急动力间 | 应急发电机 `lab_power_generator` | 主手右键，修复消耗保险丝 ×1、铜锭 ×4、红石 ×4；材料不足不扣除。每座研究所只需修复一次。 |
| B1 / D1 配电间 | 配电控制器 `lab_distribution_panel` | 修复后主手普通右键切换服务区；主手空手潜行右键切换收容区。可再次操作断电。 |
| G1 / A7 大厅 | 研究终端 `lab_research_terminal` | 服务区供电后右键领取门禁卡，并查询进度。每座设施中，每名玩家只能领取一次；背包放不下时不记作已领取。 |
| B3 / F5 核心档案库 | 档案终端 `lab_archive_terminal` | 完成本设施的分析与分离、恢复收容区供电后，提交研究记录 ×1 和分离试剂 ×1，领取核心档案 ×1、虚空晶 ×2。每座设施共用一次奖励。 |

电力状态以整座研究所为单位保存，多人共享修复和两个分区的开关状态。服务区包括 G1、G2、G3、B1；收容区包括 B2、B3。新布局共管理 881 盏灯板和工作灯，初始断电；120 处常亮光源保留照明，其中 59 处紫晶组合的表面补光持续生效，断电不会关闭晶体补光。

## 门禁与应急离开

B2 / B3 共 40 个受管门根接入收容区门禁。从房间外侧开门，需要收容区供电，并在主手或副手持有研究所门禁卡；把卡放在背包里不算手持。门禁卡可在 A7 领取，遗失后可通过纸、铁粒和研究记录合成补卡。

从房间内侧可以手动应急开门，断电或没有卡时仍可离开。原有双楼梯与货梯继续连接六层，没有额外锁住垂直逃生通路。

## 显微镜与离心机

新布局登记 42 台加工设备。在已绑定且所在分区供电的设备上右键，打开 **3 个机器槽 + 36 个玩家背包槽**的界面。机器槽依次为样本、试剂和产物；产物槽用于取出结果。

| 设备 | 样本槽 | 试剂槽 | 产物 | 耗时 |
| --- | --- | --- | --- | --- |
| 显微镜 `lab_microscope` | 原始组织样本 ×1 | 无需试剂 | 研究记录 ×1 | 100 tick，正常 20 TPS 下约 5 秒 |
| 离心机 `lab_centrifuge` | 原始组织样本 ×1 | 玻璃瓶 ×1 | 分离试剂 ×1 | 160 tick，正常 20 TPS 下约 8 秒 |

断电或产物槽无法容纳结果时暂停处理；机器物品和进度随存档保存。重新供电并清出产物空间后可继续。组织样本还会出现在科研、医疗、收容分类的补给桶及家具战利品中。

玩家自行摆放的显微镜、离心机和控制器没有研究所任务绑定，不会凭空取得某个分区的电力。已有储物柜、抽屉和工作台仍使用原来的 27 格库存与一次性战利品，打开机器、修复电源或领取任务奖励都不会刷新储物柜。

档案奖励还要求本设施实际完成过分析和分离。提交时会同时检查材料与背包空间：背包放不下全部奖励就整笔拒绝，不扣材料、不向地面丢出奖励；成功后多人共用“已领取”状态，重复点击或读档不会再次发放。

## 家具与附属接口

A3 等医疗区改用专用钢架观察床，保留原生床的两格状态、睡眠与碰撞行为；隔帘以成对轨道分隔床位。等候区改用可拼接沙发，桌面补充薄工作垫。原有 13 类储物家具的库存规则保持一致。

研究所 API 仍为 v1，公共契约兼容 Java 17；alpha.4 追加只读供电查询、可关闭的设施事件订阅和加工配方注册，旧 v1 附属无需改写。使用新增接口的附属需依赖 alpha.4 或以后版本。示例、生命周期和限制见[研究所 API](institute-api.md)及[双版附属示例](../examples/institute-addon/README.md)。

## 开发验证

发布前完整双版构建与原生测试由仓库根目录运行：

```powershell
python tools/build_dual_version.py --clean --gametests
```

在对应工程目录，使用该平台的 JDK，分别运行新增的加工和设施测试：

```powershell
.\gradlew.bat runGameTestServer -PprocessingChecks
.\gradlew.bat runGameTestServer -PoperationsChecks
.\gradlew.bat runClient -PoperationsVisualCheck
```

`InstituteOperationsVisualCheck` 使用各工程独立的 `build/operations-visual-check`，检查真实交互、门禁、加工菜单、档案奖励及医疗家具；截图在其 `screenshots` 子目录，结果标记写入 `operations-visual-result.txt`。开发检查不使用玩家已有实例或存档。两版附属示例还需在对应工程运行 `build runGameTestServer`，随后执行示例目录的 `verify_examples.py`。
